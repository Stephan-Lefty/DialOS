# So heisst der Nutzer. Eine Zeile, zwei Felder, getrennt durch "|":
#
#     Geschrieben | Gesprochen
#
# Das zweite Feld ist optional. Fehlt es, gilt das erste fuer beides.
#
# WOFUER DAS ZWEITE FELD (Stephans Beobachtung vom 2026-08-20): Michael sprach
# "Stephan" als "Stefffan" aus. Der Name des Nutzers wird bei JEDER
# Begruessung, jeder Rueckfrage und jedem Fehler gesagt - falsch ausgesprochen
# stoert er mehr als jedes andere Wort. Im zweiten Feld steht deshalb die
# Schreibweise, die richtig KLINGT:
#
#     Stephan | Steffan
#
# Geschrieben bleibt "Stephan" - fuer Briefe und Ausdrucke, wo "Steffan"
# schlicht falsch waere.
#
# ZWEIMAL NACHGEBESSERT, und beide Male hat Stephan es gehoert, nicht ich:
# erst "Stefan" statt "Stefffan" (2026-08-20), dann "Steffan" statt "Stefan"
# (2026-08-22) - die Betonung lag auf der falschen Silbe. Aus sechs
# Schreibweisen im Hoervergleich gewaehlt. Wer einen Namen einstellt, sollte
# ihn sich vorsprechen lassen, statt die naheliegende Schreibweise zu nehmen.
#
# WARUM NICHT IN DIE AUSSPRACHE-TABELLE von dialos-say.py: Dort stehen Regeln,
# die fuer ALLE Geraete gelten ("Tastatur", "ID", "DialOS"). Ein Kundenname gilt
# fuer EIN Geraet. Eine Regel pro Kunde in einer globalen Tabelle waere in einem
# Jahr eine Liste von Namen fremder Leute im Repo - und beim naechsten Kunden
# wieder falsch.
#
# DIESE DATEI IST NUR DAS BEISPIEL. Die echte heisst
# /usr/local/share/dialos/nutzer-name.txt und wird beim Aufsetzen im Buero
# angelegt. Sie liegt bewusst NICHT im Repo: Ein Kundenname gehoert nicht in die
# Versionsverwaltung.
#
# Wofuer der Name benutzt wird - und wofuer nicht - steht in
# /usr/local/bin/dialos-namen.py. Kurz: Begruessung, Entscheidungen und
# Fehlermeldungen ja; Bestaetigungen und die Zeitgrenze nein.
#
# Fehlt die Datei, bleibt es beim schlichten "Du". Alle Ansagen stimmen dann
# trotzdem - keine haengt davon ab, dass ein Name da ist.
#
# Erlaubt sind je Feld Buchstaben, Bindestrich und Leerzeichen, hoechstens 31
